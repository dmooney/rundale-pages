UI tests that hold up on a slow machine

PR #2292, part of #2287. This changes test timing only, so there is nothing visible to record. The evidence is the hosted CI runs below. They are iOS simulator runs using the Endpoint mock transport: not live gameplay, and not a physical iPhone.

The problem

Thirteen UI tests that pass on the owner's Mac failed on GitHub's hosted macos-26 runner (#2276's run 39900058884), where UI tests averaged 54 seconds each. Several of them must act while a streamed reply is still arriving. The Endpoint mock's "slow" stream paused 3 seconds between chunks, so a test had about 6 seconds to act.

The first change

The mock's slow stream pauses 6 seconds between chunks, giving about 12 seconds to act. Two waits that a slow reply must finish within were raised to keep their headroom. No assertion changes.

Runs

  • The smoke gate on the first push. It does not exercise the changed tests.
  • The full gate on the next push, with the mobile-verify-full label. Its results and each failure's assertion message will be added here.
