UI tests removed: Linux already covers them

PR #2303, part of #2287. The audit is comment 6384241953. The owner's approval is recorded in comment 6386178358. That comment and comments 6386250804 and 6386302307 record the five exceptions below. The PR deletes 12 simulator UI tests (about 555 s of the full gate) and changes nothing the app does, so there is nothing to record on screen.

The evidence is that the Linux tests the removed tests rely on catch the behaviour breaking.

Method

This ran in a Linux cloud session. For each rule:

  1. Change the engine, mod data or RundaleKit source so that the rule breaks.
  2. Run the named Linux test and confirm it fails.
  3. Revert the change with git checkout.

The tree was clean afterwards. The last column quotes where each test failed.

Audited tests that stay

These five check code in the iOS app target, which no Linux test reaches:

  • testReturningShowsWhoIsThereWithoutRepeatingTheDescription: how the title-only scene card renders.
  • testUnadvertisedCommandsWorkAndOthersAreRefused: a refused command keeps the draft.
  • testPhase2EndpointErrorNamesTheFailureCategory: RundaleEngineController maps an Endpoint error code to its failure reason.
  • testUnaddressedSpeechAsksWhoAndTheChoiceBecomesThePartner: the "Everyone here" VoiceOver label on the All choice.
  • testClarificationOptionIsTemporaryAndActionable: the "Directed to …" row the app renders for a chosen person.

Also kept: every layout, keyboard, accessibility, lifecycle and networking test, and one end-to-end test per wiring path.
